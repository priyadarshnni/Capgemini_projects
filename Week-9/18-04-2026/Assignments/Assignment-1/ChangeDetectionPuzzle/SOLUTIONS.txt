TECHNICAL DEEP DIVE:
════════════════════

CHANGE DETECTION IN ANGULAR:

1. OnPush Strategy:
   ├─ Only runs when:
   │  ├─ @Input() reference changes
   │  ├─ Event fires within component
   │  ├─ markForCheck() called
   │  └─ detectChanges() called
   └─ Does NOT run on:
      └─ Property mutations (this.prop.field = value)

2. Default Strategy:
   ├─ Runs on:
   │  ├─ Every zone.js event
   │  ├─ Every async operation
   │  ├─ Every user event
   │  └─ Every mutation
   └─ Checks actual VALUES in template

3. Change Detection Cycle:
   ┌────────────────────────────────┐
   │ Event triggers (click, async)  │
   └────────────────────────────────┘
                 ↓
   ┌────────────────────────────────┐
   │ Zone.js notifies Angular       │
   └────────────────────────────────┘
                 ↓
   ┌────────────────────────────────┐
   │ Change detection runs          │
   │ (checks bound values)          │
   └────────────────────────────────┘
                 ↓
   ┌────────────────────────────────┐
   │ Views update if values changed │
   └────────────────────────────────┘


IMMUTABLE PATTERNS (RECOMMENDED):
═════════════════════════════════

const newState = { ...oldState, fieldToUpdate: newValue };

Benefits:
- Predictable change detection
- Easy to debug
- Pairs perfectly with OnPush
- Required for NgRx/Redux patterns
- Better for time-travel debugging
- Prevents accidental mutations


═══════════════════════════════════════════════════════════════════

PERFORMANCE IMPLICATIONS:
═════════════════════════

Default Strategy:
- Pros: Easy to use, updates automatically
- Cons: Expensive, runs frequently, not scalable

OnPush Strategy:
- Pros: Highly performant, predictable, scalable
- Cons: Need to explicitly trigger updates

Immutable Pattern (with OnPush):
- Performance: Excellent
- Scalability: Excellent
- Maintainability: Excellent
- Industry standard: Yes (React uses this philosophy)

REAL-WORLD SCENARIOS:
═════════════════════

Scenario 1: Button click updates single value
→ Use: detectChanges() or new reference

Scenario 2: API response updates object
→ Use: New reference (immutable pattern)

Scenario 3: Real-time data stream
→ Use: Observables with async pipe

Scenario 4: Form changes
→ Use: Reactive forms with OnPush

Scenario 5: Complex nested state
→ Use: NgRx + immutable patterns + OnPush
